一、产品背景与目标
1.1 背景
35-50岁中产人群普遍对退休生活缺乏具体感知——知道要规划，但不知道具体想要什么样的退休生活。"凡事预则立"帮助用户通过浏览他人真实退休生活片段，逐步把模糊的退休憧憬沉淀成自己的「退休蓝图」。
1.2 MVP 目标
目标
衡量指标
验证核心用户需求
注册用户 5,000，蓝图创建率 > 40%
验证内容消费→蓝图收藏链路
内容收藏转化率 > 10%
建立初期内容供给
日均新增生活流内容 ≥ 20 条
验证留存
D7 留存 > 15%，D30 > 8%
1.3 MVP 范围边界
本期做：用户体系、退休倒计时、退休蓝图、退休生活流、许愿墙
本期不做：搭子匹配与连线、付费会员体系、蓝图导出 PDF、顾问市场、算法推荐（v1用时间序）

- AC1：微信授权失败时提示「请授权以使用完整功能」，不强制授权仍可浏览内容流（只读）
- AC2：预计退休年龄 < 当前年龄时，提示「退休年龄需大于当前年龄」
- AC3：用户资料页可随时修改昵称、头像、预计退休年龄，修改后倒计时实时更新

F2：退休倒计时
4.2.1 功能描述
首页核心展示区，给用户一个清晰的「时间锚点」——退休不是遥不可及的，它在 X 年后。配合里程碑提醒形成持续的回访驱动。
4.2.2 倒计时展示
首页倒计时模块布局：
┌─────────────────────────────┐
│  距离退休                     │
│                              │
│      18年 3个月               │  ← 大字，核心视觉
│                              │
│  预计 2044 年退休              │  ← 小字辅助
│  [修改退休年龄]                │  ← 文字链
└─────────────────────────────┘
计算规则：退休年份 = 出生年份 + 预计退休年龄，倒计时精确到月份。
4.2.3 里程碑系统
系统预设里程碑（根据距退休年数自动触发）：
里程碑触发条件
提醒内容
距退休 10 年
「现在开始规划，正是时候」+ 引导完善蓝图
距退休 5 年
「5年倒计时，退休生活清单该具体了」
距退休 3 年
「财务准备好了吗？蓝图还差哪一块？」
距退休 1 年
「一年后的生活，你准备好了吗？」
触发机制：每次用户打开小程序时检查是否跨越里程碑，跨越则在首页展示里程碑弹窗（每个里程碑只弹一次）。
生日回顾：每年生日当天（通过出生月份判断），首页展示「你的蓝图今年新增了 X 条，还有 X 个维度待完善」回顾卡片。
4.2.4 验收标准
- AC1：倒计时展示精确到月，跨年正确计算（如 2026-06 出生年1980 退休60岁 → 显示「13年6个月」）
- AC2：已退休用户（is_retired=true）首页不显示倒计时，改为显示「退休生活第 X 年」
- AC3：里程碑弹窗有「知道了」按钮，关闭后记录已展示，不再重复弹出

4.3.4 交互流程
查看蓝图（「我的」Tab → 我的蓝图）：
蓝图概览页
├── 顶部完整度进度条：「你的蓝图已填写 X/5 个维度」
├── 5个维度卡片（各展示条目数量）
└── 点击维度卡片 → 进入维度详情页
    ├── 该维度所有条目列表
    ├── [+ 添加新想法] 按钮（自填）
    └── 每条条目：内容 + 来源标注 + 编辑/删除操作
自填一条蓝图记录：
点击「+ 添加新想法」
    ↓
输入文字（必填）+ 可选添加标签
    ↓
保存 → 回到维度详情页，新条目出现在列表顶部
从生活流收藏到蓝图：
在「发现」Tab 看到一条内容
    ↓
点击内容卡片右下角「+ 加入蓝图」按钮
    ↓
弹出半屏弹窗：「加入哪个维度？」（展示5个维度选项）
    ↓
选择维度后，文字内容自动填入，来源标注为「来自 @用户昵称」
    ↓
Toast提示「已加入你的退休蓝图·住在哪」
4.3.5 验收标准
- AC1：蓝图完整度进度条实时更新，有至少1条记录的维度算「已填写」
- AC2：收藏来源被删帖后，蓝图条目仍保留，来源标注变为「来自已删除内容」
- AC3：蓝图内容最大200字，超出时输入框计数变红并阻止提交
- AC4：每个维度条目数量不限，但单次展示最多50条，下拉加载更多
- AC5：删除条目需二次确认弹窗「确认删除这条想法？」

F4：退休生活流
4.4.1 功能描述
产品的内容引擎。用户（尤其是已退休的「内容官」）发布自己的退休生活片段，规划中的用户通过浏览这些真实内容获得灵感，并一键收藏到自己的蓝图。
4.4.2 内容发布
发布入口：「发现」Tab 右上角「+」按钮（所有用户可发布）。
发布表单字段：
字段
类型
必填
限制
图片
image
否
最多3张，单张压缩至800KB以内，支持从相册选取或拍摄
正文
text
是
最少10字，最多500字
维度标签
enum（多选）
是
从5个维度中选1-3个，帮助内容归类
自定义标签
text
否
最多3个，每个不超过8字，如「#大理」「#一个人」
花费参考
text
否
选填，如「月花费约6000元」，最长30字
发布流程：
点击「+」→ 进入发布页
    ↓
填写内容（正文必填）
    ↓
选择维度标签（必选，最多3个）
    ↓
可选：添加图片、自定义标签、花费参考
    ↓
点击「发布」→ 审核（微信内容安全API自动审核）→ 通过后展示在内容流
内容审核：调用 wx.security.msgSecCheck 和 wx.security.imgSecCheck 接口，不通过则提示用户修改，不做人工审核（MVP阶段）。

├─────────────────────────────┤
│ ┌──────────────────────────┐│
│ │ [头像] 昵称  退休第3年    ││  ← 内容卡片
│ │                          ││
│ │  [图片（可选）]            ││
│ │                          ││
│ │  正文内容摘要（最多3行）   ││
│ │                          ││
│ │  #大理 #一个人  月花6000  ││
│ │                          ││
│ │  ❤️ 32  💬 8  ➕ 加入蓝图 ││
│ └──────────────────────────┘│
└─────────────────────────────┘
排序规则（MVP）：按发布时间倒序，不做算法推荐。后续版本引入基于蓝图维度的相关性排序。
内容详情页：点击卡片进入详情，展示完整正文 + 全部图片 + 评论列表。

4.4.5 验收标准
- AC1：内容发布后2秒内完成微信安全审核，通过则立即出现在内容流；不通过则提示具体原因（文字违规/图片违规）
- AC2：「加入蓝图」按钮在用户已收藏该内容到任意维度后，变为「已加入」（灰色），点击跳转到蓝图对应维度
- AC3：内容流下拉刷新 < 1.5秒，分页加载每页20条
- AC4：发布时无正文或正文不足10字，提交按钮置灰且提示字数要求
- AC5：用户可删除自己发布的内容，删除后内容从流中移除，已收藏该内容的蓝图条目来源标注更新为「来自已删除内容」

F5：霁念墙
4.5.1 功能描述
轻量级社区互动模块。用户写下一个退休霁念，其他用户可以「+1 我也想」。功能核心价值是「发现还有人和你想的一样」，强化用户对产品的归属感。

string
霁念内容，10-80字
dimension
enum
关联维度（选填，便于分类）
like_count
number
+1 数量
created_at

4.5.3 霁念墙展示
┌─────────────────────────────┐
│  [热门] [最新]               │  ← 排序切换
├─────────────────────────────┤
│ ┌──────────────────────────┐│
│ │ 「退休后想在大理租个小院    ││
│ │   种花养猫，过慢慢的生活」  ││
│ │                          ││

│ └──────────────────────────┘│
└─────────────────────────────┘
排序规则：
- 热门：按 like_count 倒序，取前100条
- 最新：按 created_at 倒序，分页加载
4.5.4 写下霁念
点击「+ 写下霁念」按钮
    ↓
填写霁念内容（10-80字，必填）
可选择关联维度标签
    ↓
提交 → 安全审核 → 出现在最新列表
每用户限制：每天最多写下3条霁念，防止刷屏。
4.5.5 +1 功能
- 已登录用户点击「+1 我也想」，计数+1，按钮变为已选中状态「✓ 我也想 (X)」
- 再次点击取消，计数-1
- 未登录用户点击触发微信登录引导
4.5.6 验收标准
- AC1：每日写下上限3条，超出后「+写下霁念」按钮置灰，提示「今日已写下3个霁念，明天再来」
- AC2：+1 操作防抖处理，300ms内重复点击只计一次
- AC3：霁念内容超80字时输入框实时计数提示，超出阻止提交
- AC4：热门排行每小时刷新一次（云函数定时任务）

七、非功能性需求
类别
要求
性能
